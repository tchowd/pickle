# Legacy deterministic-check parity audit

Audit date: **23 November 2026**. Baseline source inspected at `3163e52f8740e04214a8c2d259f1638d77dadbce`, including the then-current Save/restart test-only work. The app-only recorded-intent fix described below was then implemented and checked locally; fresh full CI and native acceptance of that change remain pending. This is an assertion mapping, not acceptance of Phase 2.

The executable is declared as `PickleChecks` in [Package.swift](../Package.swift). Its normal path in [ChecksMain.swift](../Tests/PickleCoreTests/ChecksMain.swift) registers **75 unique check functions**, counted from its actual `await run(...)` calls: Pipeline 16, Validation 19, Transport 8, Invocation 3, Streaming 5, PageContext 4, WebReference 3, Ollama 6, AnswerMarkup 4 and KnowledgeBase 7. A check can contain many assertions; 75 is not an assertion count. Explicit live-provider, benchmark and evaluator-export command branches are not part of those 75.

Rust execution evidence is the retained Mac/Windows desktop logs for source `817301f2462d34f6853a89b3c688f03151065228`, [CI run 45216660413](https://github.com/tchowd/pickle/actions/runs/45216660413). Its workspace tests passed; its Windows package jobs failed the separate capture diagnostic, so it is not a four-job green checkpoint. The mapped Rust policy/provider/app files were unchanged between that checkpoint and the baseline inspected source. Baseline test names below were matched against actual `test ... ok` records in those logs; mere function existence was not treated as execution. The new recorded-intent tests, renamed provenance test and five exact provider regressions have local evidence only, explicitly identified below. Those logs do not run the Swift suite side by side, and the current in-progress CI run is not counted as a pass. The [native record](RUNE-NATIVE-ACCEPTANCE.md) owns exact package/device outcomes.

| Label | Meaning |
|---|---|
| **D — direct predicate equivalent** | Inspected Rust implementation and assertions establish the original check's stated predicate. Fixture spelling or architecture can differ; this does not assert arbitrary-input equivalence. |
| **P — related/partial** | Relevant behavior exists and named tests execute, but one or more original assertions or fixture variants are not directly established. The missing proof is stated. |
| **Δ — implementation difference** | A concrete data/presentation/interaction difference exists. This is not automatically an approved compatibility waiver. |
| **A — absent** | No implementing behavior was found. This audit does not assign A merely because an exact test was not found. |

Mapping outcome after the local recorded-intent fix: **26 D, 47 P, two Δ, zero A** across all 75 registered checks. These are audit classifications, not 75 newly executed passes or a claim of complete equivalence.

Links below identify source suites; each Rust function name is exact and searchable in its linked module. Repeated mappings intentionally identify multiple original predicates covered by one Rust test.

## Concrete differences and next work

1. **Recorded-intent loss fixed in source; fresh CI/native verification pending.** This was a live-path difference, not just a synthetic fixture expectation. The exact original [knowledge fixture](../Tests/PickleCoreTests/KnowledgeBaseTests.swift#L38) asserts `[.adjustment, .explain, .simplify]`, with term `energy` and adjustment `Shorter`. [KnowledgeEntry.Action and initializer](../Sources/PickleCore/KnowledgeBase.swift#L6) persist those actions and the supplied question. The actual [Swift coordinator](../Sources/PickleApp/Coordinator.swift#L243) calls `adjust` with `Ask(action: .adjustment, question: label)` and `explainTerm` with `.explain` plus the **raw term**. [Its completion/record path](../Sources/PickleApp/Coordinator.swift#L322) passes that same Ask into `KnowledgeEntry` after stale-result and opt-in checks. [KnowledgeBaseView](../Sources/PickleApp/KnowledgeBaseView.swift#L4) displays the categories as **Adjustment** and **Explain**, rather than Follow-up.

   Rune now carries app-only `RecordedIntent` through [Pending and accepted recording metadata](../rune/crates/pickle-app/src/controller.rs). Explicit Explain and [adjustment button](../rune/crates/pickle-app/src/views.rs) entrypoints provide that intent; normal typed follow-ups remain literal questions. Generation still uses `ReadingAction::FollowUp` with the same internal instructions and visible labels. `history_entry` applies current-attempt/start-and-completion opt-in guards; `make_entry` records the typed category/raw question. Explicit Save reads accepted intent beside the accepted reference pointer, never a later pending request or mutable context. No provider conversation or archive schema changed.

   Before the fix, explaining `energy` and then choosing Shorter recorded `(Follow-up, "Explain “energy”")` and `(Follow-up, "Shorter")`. Rune now records `(Explain, "energy")` and `(Adjustment, "Shorter")`, consistent with its displayed action-title convention. Four new [recorded-intent regressions](../rune/crates/pickle-app/src/recorded_intent_tests.rs) passed locally: the actual Simplify → Explain → Shorter → typed-question sequence with both archives reopened; accepted metadata surviving pending/failed/cancelled/stale requests; pre-base Explain, eviction, clear/new-base/new-source resets; and opt-in/current-attempt history admission. Seven [accepted-reference tests](../rune/crates/pickle-app/src/answer_reference_tests.rs) also passed locally, including the renamed typed-intent case. The original [explicit bookmarks](../Sources/PickleApp/Bookmarks.swift#L4) contain passage/answer/source/date only, with no action/question fields; this legacy loss was demonstrated for automatic knowledge history, while Rune also preserves accepted intent in its richer explicit Save format.
2. **Highest-value missing test: repair-stream retention and event ordering.** The disconnected repair channel is present and bounded repair outcomes are tested, but neither establishes the original initial-draft → Reviewing → Refining sequence for success *and* repair failure with an actual streaming fake. Add that causal regression before claiming this check direct; no production defect is demonstrated here.
3. **Decoder fixtures added locally; finish cross-platform verification and remaining transport predicates.** Four exact original Jev/usage regressions and the strengthened invalid-account test passed in the 426-test local workspace run. No production decoder changed. Fresh Windows execution is required before promoting those five mapping rows. Full buffered writer model/usage and complete native authorization/body predicates remain partial.
4. **Add exact stale draft/result delivery races and ordinary storage failures.** Existing ID guards, cancellation and state reducers are substantial evidence. Mirror the uncooperative old/new provider callbacks, two-store append/remove interleaving and denied-write preservation rather than treating those different assertions as equivalent.
5. **Record presentation and recovery differences explicitly.** Safe CommonMark is an architectural replacement for Swift's custom block parser; exact formatting/whitespace cases remain open. Explicit Try again recovery is documented and intentional. Flow operation-list constraints are an approved stricter safety rule; they preserve the original valid fixtures while rejecting some graphs the old literal-only validator could admit. Native OS collation intentionally differs between Foundation and Windows NLS; it is not a portable promise of identical search results for every Unicode query.

No absent implementing product behavior was established solely by this 75-check mapping. The concrete recorded-intent gap has a source fix and focused local regressions; it still needs fresh CI/native verification. Other P rows are evidence gaps, not invented failures. **Do not check off the Phase 2 exhaustive fixture-equivalence item from this document.** Promote a row only after its missing predicates are asserted or a difference is explicitly accepted.
