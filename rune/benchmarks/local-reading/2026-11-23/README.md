# Synthetic Local reading investigation — 23 November 2026

These are development observations from the real Rune `Pipeline` and `OllamaProvider`, using seven fixed synthetic inputs and an already configured server. No application preferences, archives, credentials, permission grants or private passages were read by the benchmark. No models were downloaded. The app's saved model was not changed. The loopback address does not establish where inference ran; every record retains `same_device: false` and `inference_location: unverified`.

The [benchmark instructions](../../../crates/pickle-providers/examples/README.md) describe explicit `--run`, bounds and manual review. [manifest.json](manifest.json) lists 15 runs/105 cases, report hashes, the baseline revision, rejected prompt variant and final source hashes. Results are data, not golden expected answers. Sampling was not seeded; this small corpus is not a calibrated model accuracy or hardware-performance benchmark.

## Changes supported by the observations

| Observation | Resulting change |
|---|---|
| Original small-model flow generations used repeated node IDs, source sentences as edge endpoints, and invented `exact` conditions; all three baseline flow cases were rejected. | Existing extracted step labels receive finite IDs and an explicit ID-to-label map. General flows remain supported. No chart is generated by the app in place of the model. |
| Finite IDs alone allowed two returned graphs, but one included an unsupported cycle and both carried spurious conditions that passed the old literal-substring checks. | A narrowly recognized whole-source operation list now requires exactly its consecutive connections and empty conditions. Ambiguous, conditional, unknown-verb and multi-sentence inputs retain the general path. Existing source/evidence, completeness and size checks remain. |
| A shorter facts-first Expand instruction reduced verbosity but strengthened uncertainty and misattributed evidence. | That variant was rejected and the exact original prose prompt restored. The records are retained to show why concise output alone was not treated as a quality fix. |
| The installed Q6 27B model spent substantial time before visible answers and one Expand request hit the provider's 90-second deadline. | Text models whose verified capabilities include `thinking` receive `think: false`, using the existing metadata request. This requests no thinking; models that cannot disable it can use their lowest level. See [Ollama's controls](https://docs.ollama.com/capabilities/thinking). Nonthinking/unknown models and vision requests are unchanged. |
| Structured replies reported approximately 0.0005 seconds of total/first-token time despite an approximately 11-second case. | Chat timing now starts before the HTTP request. Streaming includes header delay; buffered/structured replies have no observable first-token value and report `null`. Server decode/load metrics remain server-reported. Earlier `timing.total_seconds`/`first_token_seconds` values are affected; use top-level `seconds` for their client case latency. |

## Runs and interpretation

- `baseline-1b-{1,2,3}`: original product prompt and flow format, before timing correction. Flow rejected in all three runs. Prose contained source-specific errors, including a stated three-month duration described as unspecified and an invented larger research project.
- `rejected-expand-1b-{1,2,3}`: only the attempted Expand wording changed; it was not kept. Flow format was unchanged. Rejected structured final outputs are explicitly unaccepted data.
- `finite-ids-1b-{1,2,3}`: finite IDs alone, before the whole-list guard, thinking control and timing correction. Two flow outputs passed the old validator with unsupported conditions/cycle; the third failed. These records are counterexamples, not acceptable charts.
- `finite-ids-default-thinking-q6-1`: original prose prompt and finite IDs with server-default thinking. Six of seven requests returned results; Expand failed after approximately 90 seconds. The context case took approximately 74 seconds.
- `finite-ids-thinking-control-q6-1`: corrected chat timing and advertised thinking control, before the whole-list guard. All seven returned results. Context took approximately 9.4 seconds and Expand approximately 22 seconds. Cache, network and inference hardware were uncontrolled; this is an observed pair, not a universal speedup claim.
- `final-q6-1` and `final-1b-{1,2,3}`: final source changes. All 28 pipelines returned results. Every flow contains exactly `received → validated → saved`, with empty conditions. Three small-model runs are repeated observations, not a reliability percentage.

`pipeline_succeeded` means a result was returned. `chart_validated` means the bounded structural/source checks passed. Neither means the model's prose is factually correct: every row still requires manual factual review, and Local prose remains `NotChecked`.

In particular, the final small-model follow-up in run 3 says the library **will not make** its hours permanent, while the source makes permanence conditional on attendance and future funding. Final small-model Expand outputs still invent or contradict source-specific facts: one says weather and route are unrelated to reliability, another says no weather information is supplied, and another asserts the tested route is the library's only route. Thus even a 7/7 pipeline run does not pass fidelity acceptance. The final Q6 run preserved the key trial quantities, tentative conclusion and one-route/dry-weather limits in the inspected examples, but this does not establish broader model quality or clean-client compatibility.

These checks do not exercise native selection/OCR, browser integration, audio, visual analysis or screen readers. The existing Mac bundle was deliberately left at its recorded `8d5b388` revision while capture-grant refresh remains pending. Production publishing remains deferred.
